# Deploying the review site (Railway)

Live: https://sim-review-production.up.railway.app  (Railway project `sim-review`, workspace antra-tess, service `sim-review`, volume at /data)

The image (Dockerfile) holds serve.py + static/. The 1.7 GB SQLite is NOT in the image: entrypoint.sh fetches
`$DB_URL` (R2: wfe/sim/data.sqlite.zst) onto the /data volume when the `.sha256` sidecar differs from the local copy.

Update flow after re-labeling / rebuilding:
  python3 sim/site/build.py                 # rebuilds data.sqlite + static/summary.json
  python3 sim/site/prepare_presentation.py  # if the essay changed
  python3 sim/site/publish_db.py            # uploads a zstd PATCH (prev published → now, ~30 MB) + the full snapshot; no-op if unchanged
  cd sim/site && railway up --ci            # rebuild image with new static/; boot applies the patch (or full-fetches if no patch matches)

Static-only change (no DB change): just `railway up --ci`. DB-only change: `publish_db.py` then `railway service restart --yes`.

Incremental DB updates: publish_db.py keeps the last published DB in sim/site/.published/data.sqlite and uploads
`sim/data.sqlite.patch.zst` (+ `.from` = sha it applies to) alongside the full snapshot. entrypoint.sh patches in place with
`zstd --long=31 --patch-from` when the volume's copy matches `.from` (~3.6 GB peak RSS for a few seconds; sha-verified),
otherwise downloads the full snapshot. The full-snapshot upload (~450 MB) still happens every publish so fresh volumes work;
if that becomes the bottleneck, upload it less often (the patch chain only needs the previous DB on the server).

## Agent-facing surface (added 2026-09-14)

- `AGENTS.md` (served at /agents.md, /AGENTS.md, /llms.txt; `{BASE}` is substituted with the request origin).
- `/results.md` — generated by `results_md.py` from presentation.html (essay → markdown, figure buttons → data tables,
  sample buttons → full texts, measurement.html → full measurement rationale) + static/summary.json (core tables). `?sections=` picks sections.
- `/api` index, `/api/schema` (cached after first call, ~6 s), `/api/aggregate` (group-by rates/means/θ quantiles;
  json|md|csv), `/api/export` (streaming JSONL/CSV of matching rows, own read-only connection), `/api/db` → R2 snapshot.
- Static-only change → `railway up --ci`. serve.py changes → same.
